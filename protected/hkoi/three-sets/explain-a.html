第 1 部分

甲部：選擇題

第 1 題初級組及高級組單選題1 分 · 建議 5:00

兩隻蛋和 100 層樓

重點：「最壞情況最少幾次」要同時有做法和不能更少的理由；反過來問「d 次最多能處理多少」往往最清楚。

一隻蛋從某一層或以上掉下就會破，從較低的層掉下不會破；破了的蛋不能再用，沒有破的可以再用。現在有兩隻相同的蛋和一座 100 層的大廈，要找出蛋會破的最低一層（也可能 100 層都不會破）。最壞情況下，最少要擲多少次才一定能找出答案？

  1. A7
  2. B13
  3. C14✓
  4. D19

答案與解說

答案：C

反過來問：最多擲 d 次，最多可以處理多少層？第一次應該在第 d 層擲：破了，下面 d − 1 層只剩一隻蛋，要逐層試，剛好還有 d − 1 次；沒有破，還剩 d − 1 次，下一次就在再高 d − 1 層擲，如此類推。所以 d 次最多處理 d + (d − 1) + … + 1 = d(d + 1)/2 層；第一次擲得更高，破了之後就試不完下面的層。13 次最多 91 層，不夠；14 次可以處理 105 層 ≥ 100。所以最少要 14 次。做法：第一隻蛋依次在 14、27、39、50、60、69、77、84、90、95、99、100 層擲，破了就由上一次的下一層起，用第二隻蛋逐層擲。

錯誤選項錯在哪裏

  • A用二分搜尋：log₂100 約是 7。但只有兩隻蛋：第一隻在 50 層破了，第二隻只能由 1 層開始逐層試，最壞要 50 次。
  • B13 + 12 + … + 1 = 91：13 次最多只能處理 91 層，不夠 100 層。
  • D每 10 層擲一次：最壞時第一隻蛋擲 10 次，第二隻再擲 9 次，共 19 次。這不是最好的做法：之後的間隔應該越來越小。

為何會考

最少或最多：先找界，再構造（16 屆裏 11 屆，難點庫 M26）。

出題說明（給老師）

「最少或最多：先找界，再構造」在 16 屆裏有 11 屆考過（難點庫 M26）。這是經典的兩隻蛋問題，關鍵是反過來算「d 次最多處理多少層」。三個錯誤選項分別是二分搜尋（忽略只有兩隻蛋）、算錯界線（91 層）和每 10 層一試的做法；最少次數用程式按所有策略計算過（動態規劃），題中的做法也逐層模擬過。

由結果反推，或數有多少個輸入相似選項要逐個驗證
第 2 題初級組及高級組單選題1 分 · 建議 4:00

HH 和 HT

重點：求「平均要多少次」時，按目前的狀態（例如最後一個是不是 H）列方程；失敗之後回到哪個狀態，決定了快慢。

不斷擲一枚公平的硬幣（H 是正面，T 是反面）。設 A 是第一次出現「連續兩次 H」平均要擲的次數，B 是第一次出現「H 之後緊接 T」平均要擲的次數。以下哪一項正確？

  1. AA = B = 4
  2. BA = B = 6
  3. CA = 6，B = 4✓
  4. DA = 4，B = 6

答案與解說

答案：C

用「現在的狀態」列方程。等 HH：設 a 是由頭開始還要擲的平均次數，a₁ 是最後一個是 H 時還要擲的平均次數。a = 1 + a₁/2 + a/2（擲到 H 進入狀態 H，擲到 T 留在開始）；a₁ = 1 + 0/2 + a/2（再擲到 H 就完成，擲到 T 要由頭開始）。解得 a₁ = 4，a = 6。等 HT：b = 1 + b₁/2 + b/2；b₁ = 1 + 0/2 + b₁/2（擲到 T 就完成，擲到 H 仍然是最後一個是 H）。解得 b₁ = 2，b = 4。兩個結果每兩次出現的機會都是 1/4，但失敗之後的情況不同，所以 A = 6，B = 4。

錯誤選項錯在哪裏

  • A以為連續兩次的某個結果機會是 1/4，所以平均 4 次就出現。但擲硬幣不是每兩次一組，前後會重疊，不能這樣算。
  • B知道 HH 平均要 6 次，以為 HT 也一樣。分別在於失敗之後：等 HT 時，H 之後再擲到 H，仍然是「最後一個是 H」，不用由頭開始。
  • D把兩個答案調轉了。等 HH 時，H 之後擲到 T 就要由頭開始，所以 HH 比較慢。

為何會考

期望值（高級組考過 4 次）；按狀態列方程。

出題說明（給老師）

期望值在高級組考過 4 次，2014/15 高級組就問過連續兩個正面的平均次數；實戰篇第 3 題問「剛好第 8 次」的機率，這題再進一步，把 HH 和 HT 放在一起比較。兩者每兩次出現的機會都是 1/4，平均次數卻不同，是很多人意想不到的結果。答案用程式把每個次數的機會乘上次數加起來核對過（加到 400 次）。

相似選項要逐個驗證矯枉過正的陷阱
第 3 題初級組及高級組單選題1 分 · 建議 5:00

輾轉相除最慢的一對

重點：找「最慢的輸入」時倒過來想：每一步都走得最少（這裏是商為 1），倒推出最壞的情況；輾轉相除法最慢的是相鄰的費氏數。

以下程式讀入整數 a、b（100 ≥ a > b ≥ 1），輸出迴圈的次數。在所有這樣的 (a, b) 之中，哪一對令程式的輸出最大？

int a, b, c = 0;
cin >> a >> b;
while (b != 0) {
    int r = a % b;
    a = b;
    b = r;
    c++;
}
cout << c;
  1. A(100, 99)
  2. B(100, 1)
  3. C(97, 60)
  4. D(89, 55)✓

答案與解說

答案：D

每一次 (a, b) 變成 (b, a % b)。要用最多次，每一步的商 a ÷ b（向下取整）都應該是 1，即 a = b + (a % b)。由最後倒推：最後一步之前是 (2, 1)（2 % 1 = 0），再之前是 (3, 2)、(5, 3)、(8, 5)、(13, 8)……每一對都是相鄰的費氏數。不超過 100 的最大費氏數是 89，前一個是 55：(89, 55) → (55, 34) → (34, 21) → (21, 13) → (13, 8) → (8, 5) → (5, 3) → (3, 2) → (2, 1) → (1, 0)，共 9 次。要 10 次的話 a 最少是 144，超過了 100。程式檢查了全部 4950 對，只有 (89, 55) 要 9 次。

錯誤選項錯在哪裏

  • A以為兩個數越接近越慢。100 % 99 = 1，之後 99 % 1 = 0，只要 2 次。
  • B把 % 想成每次減去 b（輾轉相減）：(100, 1) 要減 99 次。程式用 %，100 % 1 = 0，1 次就完成。
  • C97/60 接近黃金比例 1.618，但不是費氏數：要 8 次，比 (89, 55) 少 1 次。

為何會考

費氏數列式遞推（16 屆裏 7 屆，難點庫 M20）；最壞情況的輸入。

出題說明（給老師）

費氏數列式遞推在 16 屆裏有 7 屆考過（難點庫 M20），但輾轉相除法的最壞情況在初賽從未出現。這題要倒過來想：每一步的商都是 1 時最慢，倒推出來就是費氏數。三個錯誤選項分別來自「越接近越慢」「把 % 當成逐次減」和「接近黃金比例但不是費氏數」，次數都用程式算過；程式也檢查了全部 4950 對。

由結果反推，或數有多少個輸入相似選項要逐個驗證
第 2 部分

乙部：短答題

第 4 題初級組及高級組填充題2 分 · 建議 5:00

遞歸函數 f

重點：遞歸展開很長時，先試邊界附近的小例子找規律，再由大到小（或由小到大）證明規律對所有 n 成立。

以下程式輸出甚麼？

int f(int n) {
    if (n > 100) return n - 10;
    return f(f(n + 11));
}
int main() {
    long long s = 0;
    for (int n = 1; n <= 200; n++) s += f(n);
    cout << s;
}

只填一個整數。

答案與解說

答案：23150

先試 n 接近 100 的情況：f(100) = f(f(111)) = f(101) = 91；f(99) = f(f(110)) = f(100) = 91。一般 90 ≤ n ≤ 100 時 n + 11 > 100，所以 f(n) = f(n + 1)，由 f(101) = 91 一直推下去，f(90) 至 f(100) 都是 91。n < 90 時，由大到小推：n + 11 在 12 至 100 之間，f(n + 11) 已知是 91，所以 f(n) = f(91) = 91。結論：n ≤ 100 時 f(n) = 91，n > 100 時 f(n) = n − 10。總和 = 100 × 91 + (91 + 92 + … + 190) = 9100 + 14050 = 23150。

常見錯誤答案

  • 18100：以為 f(n) 一定是 n − 10。n ≤ 100 時要先算 f(n + 11)，結果全部是 91。

為何會考

遞歸求值（16 屆裏 10 屆，難點庫 R07，高級組）。

出題說明（給老師）

遞歸求值在 16 屆裏有 10 屆考過，全部在高級組（難點庫 R07）。這是著名的 McCarthy 91 函數：直接展開很長，但先試 100、99 就會發現規律，再推出 n ≤ 100 時都是 91。常見錯誤答案 18100 是以為 f(n) 一定是 n − 10。答案用程式執行核對過。

先試小的例子找規律大 n：要數，不能逐次追蹤
第 5 題初級組及高級組填充題2 分 · 建議 6:00

堆疊可以得到多少種次序？

重點：數「有多少種」時，按某個關鍵元素（這裏是 1 第幾個取出）分情況，把問題拆成兩個較小的同類問題，得出遞推式。

把 1、2、3、4、5、6 依次放入一個堆疊，途中可以隨時取出（每次取出最上面的數），最後全部取出。一共可以得到多少種不同的取出次序？

只填一個整數。

答案與解說

答案：132

設 c(n) 是 n 個數的答案。看 1 是第幾個取出的：如果 1 是第 k 個取出，那麼在它之前取出的 k − 1 個數，一定是 1 之後放入、又在 1 取出之前取出的數，即 2 至 k，它們之間有 c(k − 1) 種次序；1 取出之後，餘下的 k + 1 至 n 有 c(n − k) 種。所以 c(n) = c(0)c(n − 1) + c(1)c(n − 2) + … + c(n − 1)c(0)，c(0) = 1。c(1) = 1，c(2) = 2，c(3) = 5，c(4) = 14，c(5) = 42，c(6) = 42 + 14 + 2 × 5 + 5 × 2 + 14 + 42 = 132。（這些數叫卡塔蘭數。）

常見錯誤答案

  • 720：以為任何次序都可以。例如 3 1 2 不可能：取出 3 時 1、2 都在堆疊裏，2 在 1 上面。
  • 924：以為「放 6 次、取 6 次」可以任意先後：C(12, 6) = 924。但堆疊空的時候不能取出，要扣除這些次序。

為何會考

堆疊的取出次序（16 屆裏 12 屆，難點庫 R09）；計數的遞推。

出題說明（給老師）

由取出結果判斷堆疊在 16 屆裏有 12 屆考過（難點庫 R09），但「一共有多少種」從未考過。關鍵是按「1 第幾個取出」分情況得出遞推式（卡塔蘭數）。常見錯誤答案 720（以為甚麼次序都行）和 924（沒有扣除堆疊空了還取出的情況）。答案用程式窮舉全部 720 個次序核對過。

先試小的例子找規律大 n：要數，不能逐次追蹤
第 6 題初級組及高級組填充題2 分 · 建議 6:00

i & -i

重點：i & -i 是最低的 1，i -= i & -i 每次去掉一個 1；數「1 至 n 共有多少個 1」時逐位計算，每一位每 2k+1 個數一循環。

以下程式輸出甚麼？

long long s = 0;
for (int x = 1; x <= 1000; x++)
    for (int i = x; i > 0; i -= i & -i)
        s++;
cout << s;

只填一個整數。

答案與解說

答案：4938

i & -i 是 i 的二進制最低的那個 1（例如 12 = 1100₂，12 & -12 = 100₂ = 4）。i -= i & -i 就是把最低的 1 去掉，所以內層迴圈的次數等於 x 的二進制有多少個 1，s 就是 1 至 1000 所有數的 1 的個數之和。逐位數：第 k 位（代表 2k）在 0 至 1000 這 1001 個數之中，每 2k+1 個數一循環，前一半是 0，後一半是 1。第 0、1、2 位各有 500 個；第 3 位：1001 = 62 × 16 + 9，有 62 × 8 + 1 = 497 個；第 4 位：1001 = 31 × 32 + 9，有 31 × 16 = 496 個；第 5 至 9 位各有 489 個（例如第 9 位就是 512 至 1000）。合共 500 × 3 + 497 + 496 + 489 × 5 = 4938。

常見錯誤答案

  • 5000：以為 1 至 1000 每個數平均有 5 個 1。要逐位數：第 0、1、2 位各有 500 個數是 1，較高的位少一些。

為何會考

最低位的 1（16 屆裏 5 屆，難點庫 L29，高級組為主）；逐位計數。

出題說明（給老師）

最低位的 1（n & -n、x & (x − 1)）在 16 屆裏有 5 屆考過，多數在高級組（難點庫 L29）；2019/20 高級組考過反覆去掉最低位的 1。這題要先看出內層迴圈的次數就是 1 的個數，再逐位數 1 至 1000 有多少個 1，不能逐個數。常見錯誤答案 5000 是「平均 5 個 1」的估計。答案用程式執行核對過。

第 7 題初級組及高級組填充題2 分 · 建議 5:00

新高出現了幾次？

重點：平均值可以逐個位置相加；「第 i 個是前 i 個之中最大」的機會是 1/i，因為前 i 個數每一個做最大的機會相同。

p 是 1 至 6 的一個排列。以下程式數出 p 之中有多少個數比它前面的所有數都大（第一個數也算）。如果 p 是 1 至 6 的 720 個排列之一，每個的機會相同，程式輸出的平均值是多少？

int mx = 0, c = 0;
for (int i = 0; i < 6; i++)
    if (p[i] > mx) {
        mx = p[i];
        c++;
    }
cout << c;

填一個分數，例如 7/3（化簡與否都可以）。

答案與解說

答案：49/20

把平均值拆成每個位置的機會再相加。第 i 個數（i = 1 至 6）是新高，等於它是前 i 個數之中最大的；前 i 個數之中每一個做最大的機會相同，所以這個機會是 1/i。平均值 = 1 + 1/2 + 1/3 + 1/4 + 1/5 + 1/6 = (60 + 30 + 20 + 15 + 12 + 10)/60 = 147/60 = 49/20。

常見錯誤答案

  • 7/2：以為每個數是新高的機會都是 1/2：1 + 5 × 1/2 = 7/2。其實第 i 個數是新高的機會是 1/i，越後越小。

為何會考

等可能機率（16 屆裏 8 屆，難點庫 M14）；期望值（高級組考過 4 次）。

出題說明（給老師）

期望值在高級組考過 4 次（例如 2014/15、2023/24），初級組很少；2020/21 初級組考過排列中相對次序的機率。冷門篇第 3 題已用過「平均值逐處相加」，這題再加上「前 i 個之中最大的機會是 1/i」。常見錯誤答案 7/2 以為每個位置機會都是一半。答案用程式窮舉全部 720 個排列核對過。

先試小的例子找規律相似選項要逐個驗證
第 8 題初級組及高級組填充題2 分 · 建議 6:00

推回原狀

重點：找不變量：看一步操作對「排成一列後的逆序數」有甚麼影響；奇偶不同的狀態一定到達不了。

3 × 3 的推盤上有 1 至 8 八個方塊和一個空格（_）。每一步可以把空格上下左右的其中一個方塊推進空格。以下 4 個狀態，每個由上至下寫出三行（用 / 分隔）。哪些狀態可以推回 1 2 3 / 4 5 6 / 7 8 _？

  1. I.1 2 3 / 4 5 6 / 8 7 _
  2. II.1 2 3 / 4 _ 6 / 7 5 8
  3. III.8 2 3 / 4 5 6 / 7 1 _
  4. IV.3 1 2 / 4 5 6 / 7 8 _

填可以推回原狀的狀態編號（I = 1、II = 2、III = 3、IV = 4），由小到大，用空格分隔，例如 1 3。

答案與解說

答案：2 4

把方塊由上至下、由左至右排成一列（不計空格），數逆序對（前面的數比後面的大的對數）。左右推方塊不改變這一列的次序；上下推方塊時，被推的方塊在這一列中越過另外兩個方塊，逆序數改變 2、0 或 −2。所以逆序數的奇偶性不變。原狀的逆序數是 0（偶數），所以逆序數是奇數的狀態推不回去。I：1 2 3 4 5 6 8 7，1 個（奇數）；II：1 2 3 4 6 7 5 8，2 個（偶數）；III：8 2 3 4 5 6 7 1，13 個（奇數）；IV：3 1 2 4 5 6 7 8，2 個（偶數）。反過來，逆序數是偶數的狀態都推得回去（程式由原狀出發，找到全部 181440 個可以到達的狀態，正好是逆序數為偶數的那一半）。答案：2 4。

  • 2：以為 IV 不行。3 1 2 是三個數輪流換位，等於交換兩次，逆序數是 2（偶數），所以推得回去。

重點：最長遞增子序列的快速做法：t[k] 是長 k + 1 的子序列最小的結尾；嚴格遞增時找第一個 ≥ 的位置，不下降時找第一個 > 的位置。

int main() {
    int a[10] = {3, 1, 9, 3, 9, 2, 7, 7, 8, 8};
    int t[10], len = 0;
    for (int i = 0; i < 10; i++) {
        int lo = 0, hi = len;
        while (lo < hi) {
            int mid = (lo + hi) / 2;
            if (R) lo = mid + 1;
            else hi = mid;
        }
        t[S] = a[i];
        if (lo == len) len++;
    }
    cout << len;
}

Q1Junior and SeniorSingle answer1 marks · suggested 5:00

Two eggs and 100 floors

Key point: "Fewest in the worst case" needs both a method and a reason nothing better exists; asking the reverse, "how much can d tries handle at most?", is often clearest.

An egg breaks if dropped from a certain floor or higher, and does not break from lower floors; a broken egg cannot be used again, an unbroken one can. With two identical eggs and a 100-floor building, you must find the lowest floor from which the egg breaks (it may not break even from floor 100). In the worst case, what is the least number of drops that always finds the answer?

  1. A7
  2. B13
  3. C14✓
  4. D19

Answer and explanation

Answer: C

Ask the reverse question: with at most d drops, how many floors can be handled? The first drop should be at floor d: if it breaks, the d − 1 floors below must be tried one by one with the last egg, using exactly the d − 1 drops left; if not, d − 1 drops remain, and the next drop is d − 1 floors higher, and so on. So d drops handle at most d + (d − 1) + … + 1 = d(d + 1)/2 floors; dropping the first egg any higher leaves too many floors below if it breaks. 13 drops handle at most 91 floors, not enough; 14 handle 105 ≥ 100. So at least 14 drops are needed. A plan: drop the first egg at floors 14, 27, 39, 50, 60, 69, 77, 84, 90, 95, 99, 100 in turn; when it breaks, drop the second egg floor by floor starting just above the previous drop.

What is wrong with each wrong option

  • AUses binary search: log₂100 is about 7. But there are only two eggs: if the first breaks at floor 50, the second must try floor by floor from floor 1, up to 50 drops.
  • B13 + 12 + … + 1 = 91: 13 drops can handle at most 91 floors, fewer than 100.
  • DDrops every 10 floors: in the worst case the first egg is dropped 10 times and the second 9 times, 19 in all. This is not the best plan: the gaps should shrink as you go up.

Why it is tested

Minimum or maximum: find a bound, then a construction (11 of 16 years, bank item M26).

Notes for teachers

"Minimum or maximum: find a bound, then a construction" appeared in 11 of 16 years (bank item M26). This is the classic two-egg problem; the key is to reverse it and ask how many floors d drops can handle. The three wrong options are binary search (ignoring that there are only two eggs), a wrong bound (91 floors) and trying every 10 floors; the least number was computed by program over all strategies (dynamic programming), and the plan in the explanation was simulated floor by floor.

HH and HT

Key point: To find "how many on average", write an equation for each current state (such as whether the last toss was H); where a failure sends you decides how fast it goes.

A fair coin is tossed again and again (H is heads, T is tails). Let A be the average number of tosses until "H then H" first appears, and B the average number until "H then T" first appears. Which is correct?

  1. AA = B = 4
  2. BA = B = 6
  3. CA = 6, B = 4✓
  4. DA = 4, B = 6

Answer and explanation

Answer: C

Write equations by the current state. Waiting for HH: let a be the average number of further tosses from the start, and a₁ the number when the last toss was H. a = 1 + a₁/2 + a/2 (H moves to state H, T stays at the start); a₁ = 1 + 0/2 + a/2 (another H finishes, T sends you back to the start). Solving gives a₁ = 4 and a = 6. Waiting for HT: b = 1 + b₁/2 + b/2; b₁ = 1 + 0/2 + b₁/2 (T finishes, H still leaves the last toss as H). Solving gives b₁ = 2 and b = 4. Both pairs have chance 1/4 of appearing at any two given tosses, but what happens after a failure differs, so A = 6 and B = 4.

What is wrong with each wrong option

  • AAssumes that since a given pair of results has chance 1/4, it appears every 4 tosses on average. But tosses do not come in separate pairs; they overlap, so this does not work.
  • BKnows HH takes 6 on average and assumes HT is the same. The difference is what happens after a failure: waiting for HT, an H followed by another H still ends in H, so nothing is lost.
  • DSwaps the two answers. Waiting for HH, an H followed by T sends you back to the start, so HH is slower.

Why it is tested

Expected values (4 times in Senior papers); equations by state.

Notes for teachers

Expected values appeared 4 times in Senior papers; the 2014/15 Senior paper asked for the average number of tosses until two heads in a row. Exam style Question 3 asked for the chance of stopping exactly at toss 8; this question goes further by comparing HH with HT. Both have chance 1/4 at any two given tosses, yet their averages differ, which surprises many people. The answer was checked by program, adding up each number of tosses times its chance (up to 400 tosses).

Q3Junior and SeniorSingle answer1 marks · suggested 5:00

The slowest pair for Euclid's algorithm

Key point: To find the slowest input, think backwards: make every step as small as possible (here, quotient 1) and work back to the worst case; Euclid's algorithm is slowest on consecutive Fibonacci numbers.

This program reads integers a and b (100 ≥ a > b ≥ 1) and prints the number of loop passes. Among all such (a, b), which pair makes the output largest?

int a, b, c = 0;
cin >> a >> b;
while (b != 0) {
    int r = a % b;
    a = b;
    b = r;
    c++;
}
cout << c;
  1. A(100, 99)
  2. B(100, 1)
  3. C(97, 60)
  4. D(89, 55)✓

Answer and explanation

Answer: D

Each pass turns (a, b) into (b, a % b). To use the most passes, every quotient a ÷ b (rounded down) should be 1, that is, a = b + (a % b). Working back from the end: just before the last pass we have (2, 1) (2 % 1 = 0), before that (3, 2), (5, 3), (8, 5), (13, 8), … and every pair consists of consecutive Fibonacci numbers. The largest Fibonacci number not above 100 is 89, and the one before it is 55: (89, 55) → (55, 34) → (34, 21) → (21, 13) → (13, 8) → (8, 5) → (5, 3) → (3, 2) → (2, 1) → (1, 0), 9 passes in all. Ten passes would need a to be at least 144, more than 100. A program checked all 4950 pairs: only (89, 55) takes 9 passes.

What is wrong with each wrong option

  • AAssumes that closer numbers take longer. 100 % 99 = 1, then 99 % 1 = 0: only 2 passes.
  • BThinks of % as subtracting b each time (repeated subtraction), so (100, 1) would take 99 steps. The program uses %: 100 % 1 = 0, done in 1 pass.
  • C97/60 is close to the golden ratio 1.618, but these are not Fibonacci numbers: 8 passes, one fewer than (89, 55).

Why it is tested

Fibonacci-type recurrences (7 of 16 years, bank item M20); worst-case inputs.

Notes for teachers

Fibonacci-type recurrences appeared in 7 of 16 years (bank item M20), but the worst case of Euclid's algorithm has never appeared in the Heat. Students must think backwards: the algorithm is slowest when every quotient is 1, and working back gives Fibonacci numbers. The three wrong options come from "closer is slower", treating % as repeated subtraction, and "close to the golden ratio but not Fibonacci"; all pass counts were computed by program, which also checked all 4950 pairs.

The recursive function f

Key point: When a recursion is long to expand, try small cases near the boundary to find a pattern, then show it holds for every n by working in order.

What does this program print?

int f(int n) {
    if (n > 100) return n - 10;
    return f(f(n + 11));
}
int main() {
    long long s = 0;
    for (int n = 1; n <= 200; n++) s += f(n);
    cout << s;
}

Write one integer.

Answer and explanation

Answer: 23150

Try n near 100 first: f(100) = f(f(111)) = f(101) = 91; f(99) = f(f(110)) = f(100) = 91. In general, for 90 ≤ n ≤ 100, n + 11 > 100, so f(n) = f(n + 1), and working down from f(101) = 91, f(90) to f(100) are all 91. For n < 90, work down from larger n: n + 11 lies between 12 and 100, so f(n + 11) is already known to be 91, and f(n) = f(91) = 91. Conclusion: f(n) = 91 for n ≤ 100, and f(n) = n − 10 for n > 100. The total is 100 × 91 + (91 + 92 + … + 190) = 9100 + 14050 = 23150.

Common wrong answers

  • 18100: Assumes f(n) is always n − 10. For n ≤ 100, f(n + 11) must be found first, and the result is always 91.

Why it is tested

Recursive evaluation (10 of 16 years, bank item R07, Senior).

How many orders can a stack give?

Key point: To count the possibilities, split by what happens to one key element (here, when 1 is popped), breaking the problem into two smaller ones of the same kind, and get a recurrence.

The numbers 1, 2, 3, 4, 5, 6 are pushed onto a stack in that order, and numbers may be popped at any time (each pop takes the top number) until all have been popped. How many different pop orders are possible?

Write one integer.

Answer and explanation

Answer: 132

Let c(n) be the answer for n numbers. Look at when 1 is popped: if 1 is the kth number popped, the k − 1 numbers popped before it must have been pushed after 1 and popped before 1, so they are 2 to k, in any of c(k − 1) orders; after 1 is popped, the rest, k + 1 to n, can come out in c(n − k) orders. So c(n) = c(0)c(n − 1) + c(1)c(n − 2) + … + c(n − 1)c(0), with c(0) = 1. c(1) = 1, c(2) = 2, c(3) = 5, c(4) = 14, c(5) = 42, and c(6) = 42 + 14 + 2 × 5 + 5 × 2 + 14 + 42 = 132. (These are the Catalan numbers.)

Common wrong answers

  • 720: Assumes every order is possible. For example 3 1 2 is impossible: when 3 is popped, 1 and 2 are both on the stack with 2 above 1.
  • 924: Assumes the 6 pushes and 6 pops can come in any order: C(12, 6) = 924. But nothing can be popped from an empty stack, so those orders must be removed.

Why it is tested

Stack pop orders (12 of 16 years, bank item R09); counting with a recurrence.

Notes for teachers

Judging pop orders of a stack appeared in 12 of 16 years (bank item R09), but "how many are there in all" never has. The key is to split by when 1 is popped, giving a recurrence (the Catalan numbers). The common wrong answers are 720 (every order allowed) and 924 (not removing pops from an empty stack). The answer was checked by trying all 720 orders by program.

Q6Junior and SeniorFill in2 marks · suggested 6:00

i & -i

Key point: i & -i is the lowest 1, and i -= i & -i removes one 1 each time; to count the 1s in 1 to n, work bit by bit, each bit repeating every 2k+1 numbers.

What does this program print?

long long s = 0;
for (int x = 1; x <= 1000; x++)
    for (int i = x; i > 0; i -= i & -i)
        s++;
cout << s;

Write one integer.

Answer and explanation

Answer: 4938

i & -i is the lowest 1 in the binary form of i (for example 12 = 1100₂ and 12 & -12 = 100₂ = 4). i -= i & -i removes that lowest 1, so the inner loop runs as many times as x has 1s in binary, and s is the total number of 1s in all the numbers from 1 to 1000. Count bit by bit: among the 1001 numbers 0 to 1000, bit k (worth 2k) repeats every 2k+1 numbers, 0 in the first half and 1 in the second. Bits 0, 1 and 2 are 1 in 500 numbers each; bit 3: 1001 = 62 × 16 + 9, so 62 × 8 + 1 = 497; bit 4: 1001 = 31 × 32 + 9, so 31 × 16 = 496; bits 5 to 9 are 1 in 489 numbers each (bit 9, for example, in 512 to 1000). In total 500 × 3 + 497 + 496 + 489 × 5 = 4938.

Common wrong answers

  • 5000: Assumes each number from 1 to 1000 has 5 ones on average. Count bit by bit: bits 0, 1 and 2 are 1 in exactly 500 numbers each, and the higher bits in fewer.

Why it is tested

The lowest 1 bit (5 of 16 years, bank item L29, mainly Senior); counting bit by bit.

Notes for teachers

The lowest 1 bit (n & -n, x & (x − 1)) appeared in 5 of 16 years, mostly in Senior papers (bank item L29); the 2019/20 Senior paper asked about removing the lowest 1 repeatedly. Here students must see that the inner loop count is the number of 1s, then count the 1s in 1 to 1000 bit by bit rather than one number at a time. The common wrong answer 5000 is the estimate "5 ones on average". The answer was checked by running the program.

How many new highs?

Key point: Averages can be added position by position; the chance that the ith number is the largest of the first i is 1/i, since each of the first i is equally likely to be the largest.

p is an arrangement of 1 to 6. This program counts how many numbers in p are larger than every number before them (the first number counts). If p is one of the 720 arrangements of 1 to 6, each equally likely, what is the average output?

int mx = 0, c = 0;
for (int i = 0; i < 6; i++)
    if (p[i] > mx) {
        mx = p[i];
        c++;
    }
cout << c;

Write a fraction such as 7/3 (simplified or not).

Answer and explanation

Answer: 49/20

Split the average into the chances for each position and add. The ith number (i = 1 to 6) is a new high exactly when it is the largest of the first i numbers; each of the first i numbers is equally likely to be the largest, so the chance is 1/i. The average is 1 + 1/2 + 1/3 + 1/4 + 1/5 + 1/6 = (60 + 30 + 20 + 15 + 12 + 10)/60 = 147/60 = 49/20.

Common wrong answers

  • 7/2: Assumes each number is a new high with chance 1/2: 1 + 5 × 1/2 = 7/2. In fact the ith number is a new high with chance 1/i, smaller further along.

Why it is tested

Equally likely probability (8 of 16 years, bank item M14); expected values (4 times in Senior papers).

Notes for teachers

Expected values appeared 4 times in Senior papers (2014/15 and 2023/24, for example) and rarely in Junior; the 2020/21 Junior paper asked for the chance of a relative order within an arrangement. Rarer topics Question 3 already used "add the average place by place"; this question adds that the ith number is the largest of the first i with chance 1/i. The common wrong answer 7/2 assumes a half chance at every position. The answer was checked by trying all 720 arrangements by program.

Q8Junior and SeniorFill in2 marks · suggested 6:00

Back to the start

Key point: Look for an invariant: see what one move does to the inversion count of the tiles read in a line; states of different parity can never be reached.

A 3 × 3 sliding puzzle has eight tiles 1 to 8 and one gap (_). Each move slides a tile next to the gap (above, below, left or right) into the gap. Each of the 4 states below lists its three rows from top to bottom (separated by /). Which states can be slid back to 1 2 3 / 4 5 6 / 7 8 _?

  1. I.1 2 3 / 4 5 6 / 8 7 _
  2. II.1 2 3 / 4 _ 6 / 7 5 8
  3. III.8 2 3 / 4 5 6 / 7 1 _
  4. IV.3 1 2 / 4 5 6 / 7 8 _

Write the numbers of the states that can be slid back (I = 1, II = 2, III = 3, IV = 4), from smallest to largest, separated by spaces, for example 1 3.

Answer and explanation

Answer: 2 4

Read the tiles row by row into one line (ignoring the gap) and count the inversions (pairs where an earlier number is larger than a later one). Sliding a tile left or right does not change the order of this line; sliding a tile up or down moves it past two other tiles in the line, changing the inversion count by 2, 0 or −2. So the parity of the inversion count never changes. The start has 0 inversions (even), so states with an odd count cannot be slid back. I: 1 2 3 4 5 6 8 7, 1 inversion (odd); II: 1 2 3 4 6 7 5 8, 2 (even); III: 8 2 3 4 5 6 7 1, 13 (odd); IV: 3 1 2 4 5 6 7 8, 2 (even). Conversely, every state with an even count can be slid back (a program starting from the solved state found all 181440 reachable states, exactly the half with an even count). Answer: 2 4.

Common wrong answers

  • 1 2 3: Counts the tiles out of place: I, II and III have 2 each (even) and IV has 3, and assumes even means possible. The number out of place is not an invariant.
  • 2: Assumes IV is impossible. 3 1 2 is a rotation of three tiles, the same as two swaps, so its inversion count is 2 (even) and it can be slid back.

Why it is tested

Invariants and parity (6 of 16 years, bank item M16); inversions.

Notes for teachers

Invariants and parity appeared in 6 of 16 years (bank item M16), and inversions several times (the 2021/22 Junior paper: the fewest neighbour swaps equal the inversion count, for example). Here students must find the puzzle's invariant themselves: sliding a tile up or down passes two other tiles and changes the inversion count by an even number. The two common wrong answers come from "an even number out of place is enough" and from thinking a rotation of three tiles cannot be undone. The answer was checked by a program search of all 181440 states reachable from the start.

Stretches with sum at most 10

Key point: Two pointers: the right end moves one step at a time and the left end only moves right; with all numbers positive, the runs ending at r within the limit start at l to r, which is r − l + 1 runs.

This program counts how many runs of consecutive numbers in a (at least one number each) have a sum of at most lim (every number in a is a positive integer). (a) Fill in blanks R and S so that the program is correct. (b) What does the program print? (c) How many times in all is sum -= a[l]; carried out?

int main() {
    int a[10] = {3, 1, 4, 1, 5, 9, 2, 6, 5, 3}, lim = 10;
    int l = 0, sum = 0, cnt = 0;
    for (int r = 0; r < 10; r++) {
        sum += a[r];
        while (R) {
            sum -= a[l];
            l++;
        }
        cnt += S;
    }
    cout << cnt;
}

For R, write a condition, and for S an expression, using sum, lim, r, l, integers and operators, at most 12 boxes each (spaces not counted); for (b) and (c), write one integer.

R:S:(b):(c):

Answer and explanation

Answer: R: sum > lim; S: r - l + 1; (b): 20; (c): 8

(a) Each time r moves right, a[r] is added to sum; if sum exceeds lim, numbers are removed from the left until sum ≤ lim, so R is sum > lim. Then the runs ending at r with sum at most lim are exactly those starting at l to r (starting further left only makes the sum larger, as all numbers are positive), r − l + 1 of them, so S is r - l + 1. (b) For r = 0 to 9, the numbers of runs ending at r are 1, 2, 3, 4, 3, 1, 1, 2, 1, 2, 20 in total. Along the way, at r = 4 (sum 14) 3 and 1 are removed; at r = 5 (sum 19) 4, 1 and 5; at r = 6 (sum 11) 9; at r = 8 (sum 13) 2 and 6. (c) l only moves right, at most from 0 to 10, so the inner sum -= a[l]; runs at most 10 times altogether: the whole program does the work of one loop, not two. For this input it runs 2 + 3 + 1 + 2 = 8 times.

Common wrong answers

  • 19: (b) Writing R as sum >= lim also removes the run whose sum is exactly 10, so one run is missed.

Why it is tested

Two pointers and sliding windows (2015/16, 2024/25 and 2025/26 Junior).

Notes for teachers

Two pointers appeared a few times in the Heat (2015/16 Junior, and counting triangles in the 2025/26 Junior Paper 1 Section C), and sliding windows in the 2024/25 Junior Paper 2 Section C. Here S needs the idea that r − l + 1 runs end at r, and (c) needs the observation that l only moves right, so the inner loop runs at most n times altogether. R and S are marked over the values that can occur in the program. The answers were checked by running the program, and every listed form was substituted into it.

Q10Junior and SeniorFill in3 marks · suggested 7:00

The longest increasing subsequence

Key point: The fast method for the longest increasing subsequence: t[k] is the smallest ending of a subsequence of length k + 1; for strictly increasing, find the first position ≥ the number, and for non-decreasing, the first position >.

This program finds the length of the longest strictly increasing subsequence of a (not necessarily consecutive, for example 1 3 7 8). t[k] holds, among the numbers read so far, the smallest possible last number of a strictly increasing subsequence of length k + 1. For each number read, a binary search finds the first position in t whose value is not less than it, and the number replaces that value. (a) Fill in blanks R and S so that the program is correct. (b) What does the program print? (c) If R is written as t[mid] <= a[i], what does it print?

int main() {
    int a[10] = {3, 1, 9, 3, 9, 2, 7, 7, 8, 8};
    int t[10], len = 0;
    for (int i = 0; i < 10; i++) {
        int lo = 0, hi = len;
        while (lo < hi) {
            int mid = (lo + hi) / 2;
            if (R) lo = mid + 1;
            else hi = mid;
        }
        t[S] = a[i];
        if (lo == len) len++;
    }
    cout << len;
}

For R, write a condition such as x != 0; for S, write only an expression using lo, hi, integers and operators, in at most 10 boxes (spaces not counted); for (b) and (c), write one integer.

R:S:(b):(c):

Answer and explanation

Answer: R: t[mid] < a[i]; S: lo; (b): 4; (c): 6

(a) We want the first position in t whose value is not less than a[i]: when t[mid] < a[i] the position is to the right of mid, so lo = mid + 1; otherwise it is mid or to its left, so hi = mid. So R is t[mid] < a[i]. When the loop ends, lo = hi is that position, so S is lo (hi also works). If the position is len, every value in t is smaller than a[i], so a[i] is added at the end and len grows by 1. (b) t changes as follows: 3 → [3]; 1 → [1]; 9 → [1, 9]; 3 → [1, 3]; 9 → [1, 3, 9]; 2 → [1, 2, 9]; 7 → [1, 2, 7]; 7 → [1, 2, 7]; 8 → [1, 2, 7, 8]; 8 → [1, 2, 7, 8]. The output is 4 (for example 1 3 7 8). (c) With <=, the search finds the first position greater than a[i], so equal numbers can be added after each other: after the first 7 numbers t is [1, 2, 7]; the second 7 → [1, 2, 7, 7]; 8 → [1, 2, 7, 7, 8]; 8 → [1, 2, 7, 7, 8, 8]. The output is 6, the longest non-decreasing subsequence 1 2 7 7 8 8.

Common wrong answers

  • 4: (c) Assumes <= gives the same result. After the change the search finds the first position greater than a[i], so equal numbers extend the sequence, and the program finds the longest non-decreasing subsequence: 1 2 7 7 8 8, of length 6.

Why it is tested

Binary search boundaries (7 of 16 years, bank item R13); the longest increasing subsequence (a rare technique).

Notes for teachers

The longest increasing subsequence has never appeared in the Heat and is a technique beyond the Senior level; but the blanks only test binary search boundaries (bank item R13, 7 of 16 years) and the difference between < and <=. (c) shows that changing one symbol makes the same program find something else. S is marked by its effect: lo = hi when the loop ends, so hi also works. The answers were checked by running the program, and every listed form was substituted into it and compared with answers found by trying every subsequence.
