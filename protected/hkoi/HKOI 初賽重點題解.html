第 1 題兩組適用限時 15 秒多選題

哪些寫法會輸出 2.5？

考點：int 除以 int 會捨去小數。要得到小數，必須在做除法之前，把其中一邊變成 double。

以下哪些寫法會輸出 2.5？（可選多於一項）

  1. Acout << 5 / 2.0;✓
  2. Bcout << (double)(5 / 2);
  3. Ccout << (double)5 / 2;✓
  4. Dcout << 5 / 2 * 1.0;

答案與解釋

答案：A、C

關鍵是做除法那一刻，兩邊是甚麼類型：只要其中一邊是 double，就會做小數除法；兩邊都是 int，結果的小數部分就會被捨去。5 / 2.0 的 2.0 是 double，所以得 2.5。(double)5 / 2 的 (double) 只作用在 5 上，5 先變成 5.0，再除以 2，得 2.5。另外兩個寫法都是先用整數算出 2，cout 輸出 2.0 時只會顯示 2。

錯誤選項錯在哪裏

  • B括號裏的 5 / 2 先用整數算出 2，之後才轉成 double，已經太遲，輸出 2。
  • D由左至右計算：5 / 2 先得 2，再乘 1.0 仍是 2，輸出 2。

為何選這題

整數除法是初級組最常考的語言細節。學生大多知道 5 / 2 等於 2，但遇到強制轉換和計算次序就容易出錯。設計成多選題，學生就要逐個寫法判斷，不能只認出最明顯的 5 / 2.0。

要教同學的重點

  • 看做除法那一刻兩邊的類型，而不是看結果存進甚麼變量。
  • (double)(a / b) 太遲；(double)a / b 才對。
  • 同級的 * 和 / 由左至右計算，所以 5 / 2 * 1.0 先做 5 / 2。
  • 負數的整數除法同樣是直接捨去小數部分：-7 / 2 等於 -3，不是 -4。

第 2 題兩組適用限時 10 秒是非題

0.1 + 0.2 == 0.3？

考點：double 和 float 大多只能儲存近似值，所以不要用 == 比較兩個計算出來的小數。

是非題：在 C++ 中，0.1 + 0.2 == 0.3 的結果是 true。

  1. A對
  2. B錯✓

答案與解釋

答案：B

double 用二進制儲存小數。0.1、0.2 和 0.3 在二進制都是無限循環小數，就像十進制的 1/3 = 0.333…，所以只能存最接近的近似值。0.1 + 0.2 的結果約是 0.30000000000000004，而 0.3 存成約 0.29999999999999999，兩者差了一點點，所以 == 得出 false。

0.1 + 0.2  ->  0.30000000000000004
0.3        ->  0.29999999999999999
0.25 + 0.5 == 0.75  ->  true

錯誤選項錯在哪裏

  • A在數學上相等，但電腦只能儲存這三個小數的近似值，兩邊差了一點點。

為何選這題

歷屆考過「每次加 0.1，直至等於 42.0 才停」這類迴圈，它可能永遠停不下來。這個概念一說就明白，但不知道原理就很容易答錯，所以用一題 10 秒的是非題提醒就足夠。

要教同學的重點

  • 為甚麼 0.1 不能準確儲存：一個分數化成最簡分數後，分母只含質因數 2 和 5，才能寫成有限小數；在二進制，分母要是 2 的冪才行。0.1 = 1/10，分母有因數 5，所以在二進制裏寫不完。
  • 0.5、0.25、0.125 這些小數（化成分數後，分母是 2 的冪）可以準確儲存，所以 0.25 + 0.5 == 0.75 是 true。
  • 比較小數時，改為檢查兩者的差是否很小，例如 fabs(a - b) < 1e-9。
  • 迴圈條件寫成 x != 42.0 這類，可能永遠不會停。

第 3 題兩組適用限時 15 秒單選題

else 屬於哪一個 if？

考點：else 與最近、而且還未配對的 if 配對；C++ 不看縮排。

以下程式的輸出是甚麼？

int x = 5, y = 0;
if (x > 3)
    if (x > 8)
        y = 1;
else
    y = 2;
cout << y;
  1. A0
  2. B2✓
  3. C編譯錯誤
  4. D視乎編譯器而定

答案與解釋

答案：B

C++ 不理會縮排。else 一定與最近、而且還未配對的 if 配對，即 if (x > 8)。所以程式的意思是：如果 x > 3，就再看 x > 8；x > 8 不成立，於是執行 else，y 變成 2。縮排故意寫得像 else 屬於外面的 if，選 0 的同學就是被縮排騙了。

錯誤選項錯在哪裏

  • A被縮排騙了：以為 else 屬於外面的 if (x > 3)。
  • C以為縮排不對就不能編譯。C++ 完全不理會縮排。
  • DC++ 有明確規定：else 一定與最近、而且還未配對的 if 配對，所以結果是確定的。

為何選這題

if / else 的結構陷阱在初級組十分常見。這題只有 7 行，卻能清楚分辨學生是看程式結構，還是只看縮排。

要教同學的重點

  • else 永遠與最近、還未配對的 if 配對。
  • C++ 不看縮排，縮排只是方便人閱讀。想改變配對，就要加大括號 { }。
  • 做題時，先自己在紙上補回大括號，再追蹤程式。

第 4 題兩組適用限時 15 秒多選題

50000 × 50000 會不會溢出？

考點：int 乘 int 的結果仍是 int。要避免溢出，必須在乘法之前把其中一個數變成 long long。

已知 int a = 50000, b = 50000;。以下哪些寫法能令 c 得到正確的 2500000000（即 a × b）？（可選多於一項）

  1. Along long c = (long long)(a * b);
  2. Blong long c = a * b * 1LL;
  3. Clong long c = (long long)a * b;✓
  4. Dlong long c = 1LL * a * b;✓

答案與解釋

答案：C、D

這題和第 1 題（哪些寫法會輸出 2.5）是同一個道理：決定結果的是做乘法那一刻，兩邊是甚麼類型。int 乘 int 的結果也是 int，而 50000 × 50000 = 2500000000，超出了 int 的上限 2147483647，會溢出。(long long)a * b 的轉換只作用在 a 上，a 先變成 long long，乘法就用 long long 計算。1LL * a * b 由左至右，先算 1LL * a，得到 long long，再乘 b。另外兩個寫法都是先用 int 算 a * b，已經溢出。

錯誤選項錯在哪裏

  • A括號裏的 a * b 已經用 int 算完並溢出，之後才轉換，太遲了。
  • B由左至右計算，先算 a * b，已經溢出，之後再乘 1LL 也救不回。

為何選這題

學生最常以為「結果存進 long long 就安全」。這題的四個寫法和第 1 題的四個寫法一一對應，老師可以看看同學能否自己發現兩題是同一個道理。

要教同學的重點

  • int 的上限是 2³¹ − 1 = 2147483647，約 2.1 × 10⁹。
  • long long c = a * b; 也不夠：a * b 先用 int 計算，已經溢出。
  • 要寫 1LL * a * b 或 (long long)a * b，在乘法之前就換成 long long。
  • 嚴格來說，有號整數溢出在 C++ 是未定義行為；不過在一般電腦上，結果通常會「繞回」變成負數（例如 2147483647 + 1 變成 -2147483648），歷屆題目也問過這一點。最穩妥的做法是根本不讓它溢出。

第 5 題兩組適用限時 30 秒單選題

迴圈結束後 i 是多少？

考點：迴圈正常結束時，迴圈變量停在第一個令條件不成立的值（這裏是 6）。在 for 裏面用 int 宣告的變量是另一個變量，只在迴圈裏有效，而且會遮住外面同名的變量。

以下兩個程式只差一個 int。它們依次輸出甚麼？

程式一
int i = 0, c = 0;
for (i = 1; i <= 5; i++)
    c++;
cout << i;
程式二
int i = 0, c = 0;
for (int i = 1; i <= 5; i++)
    c++;
cout << i;
  1. A5 和 5
  2. B6 和 6
  3. C5 和 0
  4. D6 和 0✓

答案與解釋

答案：D

程式一：迴圈用的是外面那個 i。i 由 1 數到 5，之後再加 1 變成 6，條件 i <= 5 不成立，迴圈才結束，所以輸出 6。程式二：在 for 裏面寫 int i，等於另外宣告了一個新的變量，名字也叫 i，而且只在迴圈裏存在。迴圈改的是這個新的 i，外面的 i 從來沒有被改過，仍然是 0。迴圈結束後，新的 i 就消失了，cout << i 用的是外面的 i，所以輸出 0。

錯誤選項錯在哪裏

  • A以為迴圈結束時 i 停在 5，又以為程式二迴圈裏的 i 就是外面的 i。
  • B程式一答對了，但以為程式二迴圈裏的 i 就是外面的 i。
  • C程式二答對了，但以為迴圈結束時 i 停在 5。

為何選這題

學生常以為迴圈結束時 i 停在 5；就算記得「迴圈結束後 i 等於終止值加 1」，也會以為任何寫法都是這樣，忽略了 for (int i ...) 會另外宣告一個 i。把兩個只差一個 int 的程式放在同一題，正好一次過糾正這兩個誤解。

要教同學的重點

  • for (i = 1; i <= 5; i++) 結束後，i 是 6，不是 5。
  • for (int i = ...) 會宣告一個新的 i，只在迴圈裏有效，外面的 i 不受影響。
  • 兩個變量同名時，裏面的會遮住外面的（英文叫 shadowing）。追蹤時要分清楚每一行用的是哪一個。

第 6 題兩組適用限時 30 秒單選題

引用參數：兩個名字，同一個變量

考點：參數寫成 int &x，函數就會直接改調用者的變量。兩個參數都是同一個變量的別名時，改其中一個，另一個也會跟着變。

以下程式的輸出是甚麼？

void f(int &x, int &y) {
    x = x + 1;
    y = y * 2;
}
int main() {
    int a = 3, b = 3;
    f(a, a);
    f(b, a);
    cout << a << " " << b;
}
  1. A16 4✓
  2. B3 3
  3. C12 4
  4. D8 4

答案與解釋

答案：A

int &x 表示 x 不是副本，而是傳進來那個變量的另一個名字。f(a, a)：x 和 y 都是 a 本身。x = x + 1 令 a 變成 4，y = y * 2 再令 a 變成 8。f(b, a)：x 是 b，y 是 a。b 變成 4，a 變成 16。所以輸出 16 4。

錯誤選項錯在哪裏

  • B以為參數是按值傳遞，函數無法改變外面的變量。
  • C以為 f(a, a) 裏的 x 和 y 是兩個獨立的副本：y 由 3 開始，乘 2 得 6，a 最後變成 6；第二次調用後 a 變成 12。
  • D以為第二次調用 f(b, a) 只會改 b，不會改 a。

  • int x 是副本，函數裏怎樣改都不影響外面；int &x 是同一個變量的另一個名字。
  • f(a, a) 時，x 和 y 都是 a，要按次序逐句改 a 的值。

嵌套迴圈裏的 break

考點：break 只跳出最內層、包着它的那個迴圈；continue 只跳過這一次餘下的語句，然後進入下一次。

以下程式的輸出是甚麼？

int c = 0;
for (int i = 0; i < 3; i++)
    for (int j = 0; j < 3; j++) {
        if (j == i) break;
        c++;
    }
cout << c;
  1. A3✓
  2. B0
  3. C6
  4. D9

答案與解釋

答案：A

break 只會跳出它所在的那一層迴圈，即內層的 j 迴圈；外層的 i 迴圈會繼續。i = 0 時，j = 0 就 break，c 不變；i = 1 時，j = 0 令 c 加 1，j = 1 就 break；i = 2 時，j = 0 和 1 令 c 加 2，j = 2 就 break。共 0 + 1 + 2 = 3。

  • C以為 break 像 continue，只跳過這一次。
  • D以為 break 沒有作用。

要教同學的重點

  • break：跳出最近的一層迴圈。
  • continue：跳過這一次剩下的語句，直接進入下一次。
  • 遇到嵌套迴圈，用表格列出 i、j 和 c，逐行追蹤。

三層迴圈做了幾次

考點：內層迴圈的起點取決於外層變量時，不能直接把各層的次數相乘。j 由 i + 1 開始、k 由 j + 1 開始，就等於「選出 3 個不同的數」。

以下程式的輸出是甚麼？

int c = 0;
for (int i = 1; i <= 6; i++)
    for (int j = i + 1; j <= 6; j++)
        for (int k = j + 1; k <= 6; k++)
            c++;
cout << c;
  1. A216
  2. B120
  3. C20✓
  4. D56

答案與解釋

答案：C

c 數的是有多少組 i < j < k，而三個數都在 1 至 6 之間，即從 1 至 6 中選出 3 個不同的數，不計次序。每組 3 個數只會以「由小到大」的次序出現一次，所以答案是 C(6, 3) = (6 × 5 × 4) ÷ (3 × 2 × 1) = 20。

錯誤選項錯在哪裏

  • A以為每層迴圈都做 6 次：6 × 6 × 6。
  • B算了 6 × 5 × 4，但這是把同一組數的不同次序都計算在內；每組數只會出現一次，要再除以 3 × 2 × 1。
  • D以為 j 由 i 開始、k 由 j 開始，即三個數可以相同。

為何選這題

嵌套迴圈計數是歷屆出現得最多的題型之一，初級組和高級組都經常考。兩層的版本（j 由 i + 1 開始：5 + 4 + 3 + 2 + 1 = 15）大部分同學會做，所以這裏用三層。四個選項正好是四種數法。

要教同學的重點

  • 先問自己：c 數的是甚麼？這裏是「從 1 至 6 中選 3 個數，由小到大排列」的組數。
  • 兩層版本 for (j = i + 1; ...) 可以逐行相加：5 + 4 + 3 + 2 + 1 + 0 = 15，即 C(6, 2)。
  • 三層而且嚴格遞增時，次數是 C(n, 3) = n(n − 1)(n − 2) ÷ 6。
  • 如果三個數可以相同（例如 j 由 i 開始），答案就會改變，要重新數。

考點：找最小值或最大值時，初值要用 a[0]。用 0 做初值，找最小值時遇到全是正數、找最大值時遇到全是負數，就會出錯。

閏年的條件

考點：&& 比 || 先計算。寫完組合條件之後，要用幾個特別的例子代入檢查，例如 1900 和 2000。

閏年的定義：能被 4 整除但不能被 100 整除，或者能被 400 整除。以下哪一個條件能正確判斷 y 是不是閏年？

  1. Ay % 4 == 0 && y % 100 != 0 || y % 400 == 0✓

  3. Cy % 4 == 0 && (y % 100 != 0 || y % 400 != 0)
  4. Dy % 400 == 0 || y % 4 == 0

答案：A

把選項代進去

考點：看不出程式的規律時，就把選項逐個代入。不要憑直覺以為輸入越大，結果就越大。

函數 f 如下。以下哪一個輸入會令 f(x) 的返回值最大？

int f(int x) {
    int c = 0;
    while (x != 1) {
        if (x % 2 == 0) x /= 2;
        else x = 3 * x + 1;
        c++;
    }
    return c;
}

  2. B7✓
  3. C8
  4. D16

答案與解釋

答案：B

7 → 22 → 11 → 34 → 17 → 52 → 26 → 13 → 40 → 20 → 10 → 5 → 16 → 8 → 4 → 2 → 1   (16)

  • Af(6) = 8，比 f(7) 小。

    if (a == 0 || b == 0) return 1;
    return f(a - 1, b) + f(a, b - 1);
}

  1. A12
  2. B7
  3. C35✓
  4. D20

答案：C

a=0      1    1    1    1
a=1      1    2    3    4
a=2      1    3    6   10
a=3      1    4   10   20
a=4      1    5   15   35

第 14 題兩組適用限時 10 秒單選題教學題

'q' ^ 32 是甚麼？

考點：char 其實是數字（ASCII 碼）。大小寫字母相差 32，而且只差在代表 32 的那一位，所以 c ^ 32 可以切換英文字母的大小寫。

以下程式的輸出是甚麼？

char c = 'q' ^ 32;
cout << c;
  1. AQ✓
  2. Bq
  3. C81
  4. D亂碼

答案與解釋

答案：A

字元其實是數字：'q' 的 ASCII 碼是 113，二進制是 0111 0001；32 是 0010 0000。XOR 會把代表 32 的那一位反轉：0111 0001 ^ 0010 0000 = 0101 0001 = 81，即 'Q'。c 是 char，所以 cout 印出字元 Q，而不是 81。

'q' = 113 = 0111 0001
 32 =       0010 0000
  ^ =  81 = 0101 0001 = 'Q'

錯誤選項錯在哪裏

  • B以為 ^ 32 沒有改變任何東西，或者把 ^ 當成 |（'q' | 32 仍然是 'q'）。
  • C算對了數值，但忘了 c 是 char，cout 會印出字元，而不是數字。
  • D以為 ^ 是次方。在 C++ 中，^ 是 XOR，不是次方。
教學題：重點是記住「字元就是數字」和「大小寫只差代表 32 的那一位」。

為何選這題

字元與數字互換在兩組都經常出現，近兩屆也都有考。這是一題教學題：題目不難，但記住這兩點之後，以後看到 c - 'a'、c ^ 32 這類寫法就不會慌。

要教同學的重點

  • 數字字元轉數值：c - '0'；數值轉數字字元：'0' + d。
  • 字母序號：c - 'a'（'a' 是 0），或 c - 'a' + 1（'a' 是 1）。
  • 大小寫相差 32：'A' + 32 等於 'a'；c ^ 32 可以切換大小寫。
  • 注意：'0' + d、'A' + 32 的結果是 int，直接用 cout 會印出數字（cout << 'A' + 32; 印出 97）；要存進 char 變量，或寫成 (char)('A' + 32)，才會印出字元。c ^ 32 只適用於英文字母。
  • 變量是 char 就印出字元；是 int 就印出數字。

     6 = 0110

XOR 的抵消

考點：a ^ a = 0、a ^ 0 = a，而且 XOR 的次序可以隨意調換。所以如果 a ^ x = b，那麼 x = a ^ b。

已知 int a[5] = {7, 12, 7, 5, x};。要令這五個數全部 XOR 起來的結果是 6，x 應該是多少？（7 = 0111，12 = 1100，5 = 0101，6 = 0110）

  1. A9（1001）
  2. B6（0110）
  3. C15（1111）✓
  4. D3（0011）

答案與解釋

答案：C

XOR 有三個重要性質：a ^ a = 0（相同的數會互相抵消）、a ^ 0 = a，以及次序可以隨意調換。所以兩個 7 可以放在一起抵消，剩下 12 ^ 5 ^ x = 6。12 ^ 5 = 1100 ^ 0101 = 1001 = 9，所以 9 ^ x = 6。兩邊再同時和 9 做 XOR，得 x = 9 ^ 6 = 1001 ^ 0110 = 1111 = 15。

7 ^ 7     = 0
12 ^ 5    = 1100 ^ 0101 = 1001 = 9
x = 9 ^ 6 = 1001 ^ 0110 = 1111 = 15

錯誤選項錯在哪裏

  • B以為 x 就等於目標值。
  • D把 XOR 當成減法：9 − 6 = 3。

  • 解方程：a ^ x = b，兩邊都 XOR a，得 x = a ^ b。

  1. A4✓
  2. B6
  3. C2
  4. D86

答案：A

x & 1 取出 x 最右邊那一位（0 或 1），x >>= 1 把 x 向右移一位，即去掉最右邊那一位。所以這個迴圈逐位檢查，c 數的是二進制裏 1 的個數。45 = 32 + 8 + 4 + 1，二進制是 101101，共有 4 個 1。

x = 22 (10110)    c = 1
x = 11 (1011)     c = 2
x =  5 (101)      c = 3
x =  2 (10)       c = 3
x =  1 (1)        c = 4

  • C數了 0 的個數。
  • D以為 x & 1 就是 x，結果把每一步的 x 都加起來：45 + 22 + 11 + 5 + 2 + 1 = 86。

  • n & -n：只留下最低位的 1，例如 12（1100）變成 4（0100）。
  • x & (x - 1)：去掉最低位的 1，例如 12（1100）變成 8（1000）。
  • 原因：-n 等於「n 的每一位反轉，再加 1」，所以最低位的 1 和它右邊的 0 不變，左邊的位全部相反。x − 1 則會把最低位的 1 變成 0，並把它右邊的 0 全部變成 1。
  • x > 0 時，(x & (x - 1)) == 0 表示 x 是 2 的冪。

堆疊和隊列

考點：堆疊後進先出（LIFO），隊列先進先出（FIFO）。遇到這類題目，把每串操作都模擬一次。

以下哪一串操作，用堆疊和用隊列 pop 出來的次序完全一樣？

  1. Apush 1, push 2, pop, pop
  2. Bpush 1, pop, push 2, pop✓
  3. Cpush 1, push 2, pop, push 3, pop
  4. Dpush 1, push 2, push 3, pop

答案與解釋

答案：B

堆疊是「後進先出」：pop 拿走最後放進去的；隊列是「先進先出」：pop 拿走最早放進去的。如果每次 pop 時裏面都只有一個元素，堆疊和隊列都只能拿走那一個，結果一定相同。第二個選項正是這樣：每 push 一個就立即 pop。

錯誤選項錯在哪裏

  • A堆疊得 2、1，隊列得 1、2。
  • C堆疊得 2、3，隊列得 1、2。
  • D堆疊得 3，隊列得 1。

為何選這題

堆疊、隊列和鏈表的性質在兩組都經常出現，2024/25 和 2025/26 兩屆的初級組和高級組卷一都有這類題目。把四串操作都模擬一次，就能練熟兩者的分別。

要教同學的重點

  • 堆疊：後進先出，就像一疊碟子，只能拿走最上面的一隻。
  • 隊列：先進先出，就像排隊，先到先得。
  • 模擬時把容器裏的內容寫出來，每一步都更新。

認出排序算法

考點：認出排序算法時，看第一輪做了甚麼：選擇排序把最小的數換到最前；冒泡排序把最大的數推到最後；插入排序把下一個數插入前面已排好的部分。

把 5 3 8 1 9 2 由小到大排序。某個算法做完第一輪後，數列變成 1 3 8 5 9 2。這是哪一種排序？

  1. A選擇排序✓
  2. B冒泡排序
  3. C插入排序
  4. D合併排序

答案：A

選擇排序每一輪找出未排序部分中最小的數，和未排序部分最前面的數交換。第一輪找到最小的 1，和第一個數 5 交換，得到 1 3 8 5 9 2，其餘的數位置不變。

原本　　　5 3 8 1 9 2
選擇排序　1 3 8 5 9 2
冒泡排序　3 5 1 8 2 9
插入排序　3 5 8 1 9 2
合併排序　3 5 1 8 2 9

錯誤選項錯在哪裏

容斥原理

考點：容斥原理：「A 或 B」的個數 = A 的個數 + B 的個數 − 「A 和 B」的個數。計算「同時被兩者整除」的數，要用最小公倍數，不是直接相乘。

1 至 100 之中，能被 4 或 6 整除的數有多少個？

  1. A41
  2. B37
  3. C25
  4. D33✓

答案與解釋

答案：D

4 的倍數有 25 個（100 ÷ 4），6 的倍數有 16 個（100 ÷ 6 的整數部分）。同時是兩者倍數的數，是 4 和 6 的最小公倍數 12 的倍數，共 8 個（100 ÷ 12 的整數部分）。它們被數了兩次，要減去一次：25 + 16 − 8 = 33。

錯誤選項錯在哪裏

  • A沒有減去同時是 4 和 6 的倍數的數。
  • B以為重複的是 24（4 × 6）的倍數，其實是最小公倍數 12 的倍數。
  • C只數了 4 的倍數。

為何選這題

用公式代替迴圈的題目在兩組都經常出現，2025/26 兩組都考了。卷一的程式題常常要計算「迴圈做了幾次」，用容斥原理比逐個數快得多。

循環賽的總分

考點：比賽題先算總場數，以及每場產生的總分，再考慮最多或最少的情況。

5 隊進行循環賽，每兩隊比賽一場。贏一場得 3 分，和局雙方各得 1 分，輸一場得 0 分。全部隊伍的總分最多是多少？

  2. B30✓
  3. C60
  4. D15

答案：B

由目標倒推

考點：求最少步數時，可以由目標倒推。正向「先乘到最大，再一直加」通常不是最好的方法。

由 1 開始，每一步可以加 1 或者乘 2。最少要多少步才能得到 100？

  1. A7
  2. B8✓
  3. C42
  4. D99

答案與解釋

答案：B

由 100 倒推：偶數就除以 2，奇數就減 1。100 → 50 → 25 → 24 → 12 → 6 → 3 → 2 → 1，共 8 步。這樣倒推得出的步數最少，而且比正向逐步嘗試快得多。

錯誤選項錯在哪裏

  • D只用加 1。

找不變的量

考點：找「每一步都不變的量」（例如總和、奇偶），用它判斷最後的結果。

黑板上寫着 1 至 10 這十個數。每次擦去其中兩個數 a 和 b，再寫上 |a − b|。重複這樣做，直至只剩下一個數。這個數一定是：

  2. B偶數
  3. C0

答案與解釋

答案：A

三堆石子的遊戲

考點：博弈題由終局倒推：能走到必敗局面的，就是必勝局面；無論怎樣走都只能走到必勝局面的，就是必敗局面。

有三堆石子，分別有 2、3、4 顆。兩人輪流取石子，每次只可以從其中一堆取走任意顆數（至少 1 顆）。取走最後一顆石子的人勝出。先手第一步應該怎樣取，才能保證勝出？

  1. A把 4 顆那一堆全部取走
  2. B從 4 顆那一堆取走 3 顆✓
  3. C從 3 顆那一堆取走 1 顆
  4. D先手無論怎樣取都會輸

答案與解釋

答案：B

由終局倒推：（1）只剩兩堆數量相同的石子（例如 2、2）時，輪到的人必輸，因為對手每次都在另一堆取同樣的數量，最後一顆一定由對手取走。（2）剩下 1、2、3 時，輪到的人也必輸：無論他怎樣取，對手都能令局面變成兩堆數量相同。例如他取走 1 顆那一堆，對手就從 3 顆那一堆取 1 顆，剩下 2、2。（3）所以先手應該從 4 顆那一堆取走 3 顆，留下 1、2、3 給對手。

延伸：把各堆數量 XOR 起來，結果是 0 就是必敗局面。
2 ^ 3 ^ 4 = 5（不是 0，先手必勝）
2 ^ 3 ^ 1 = 0（取走 3 顆後，留給對手必敗局面）

錯誤選項錯在哪裏

  • A剩下 2、3。對手從 3 顆那一堆取 1 顆，剩下 2、2，之後對手只要模仿你，就能取得最後一顆。
  • C剩下 2、2、4。對手把 4 顆那一堆全部取走，剩下 2、2，之後模仿你就能勝出。
  • D先手其實有必勝的走法：從 4 顆那一堆取走 3 顆。

為何選這題

博弈題（必勝與必敗局面）在兩組都考過，形式包括取石子、輪流移除、在棋盤上放「車」和井字過三關等，共通點都是由終局倒推。只有一堆、每次取 1 至 k 顆的遊戲，可以靠「留下 k + 1 的倍數」這條公式；三堆石子的規律（把各堆數量 XOR 起來）很難自己想到，所以要真正用倒推來思考，比歷屆題目更深一點。

要教同學的重點

  • 必敗局面：無論怎樣走，對手都有辦法應付。
  • 必勝局面：至少有一種走法，能留給對手一個必敗局面。
  • 兩堆數量相同：後手只要模仿對手，就能取勝。
  • 延伸：不論有多少堆，把各堆數量 XOR 起來，結果是 0 就是必敗局面。

Which lines print 2.5?

Key point: int divided by int drops the fraction. To get a decimal result, one side must become a double before the division happens.

Which of the following print 2.5? (Select all that apply.)

  1. Acout << 5 / 2.0;✓
  2. Bcout << (double)(5 / 2);
  3. Ccout << (double)5 / 2;✓
  4. Dcout << 5 / 2 * 1.0;

Answer and explanation

Answer: A, C

What matters is the types at the moment the division happens. If either side is a double, the division keeps the decimal part; if both sides are ints, the decimal part is thrown away.   • (double)(a / b) is too late; (double)a / b is correct.

0.3        ->  0.29999999999999999

Answer: C, D

    c++;

  2. B6 and 6

Answer: D

  • After for (i = 1; i <= 5; i++) finishes, i is 6, not 5.
  • for (int i = ...) creates a new i that exists only inside the loop; the outer i is unaffected.

Key point: Binary search requires data in order (increasing or decreasing) and direct access by position, as in an array.

Which of these can be searched for x efficiently with binary search, without rearranging the data first?

  4. DAn almost sorted array with just two numbers swapped

Answer: C

An array sorted from largest to smallest meets both. A linked list may be sorted, but reaching the middle means walking from the head one node at a time.

Why the other options are wrong

  • ABinary search needs the data in order.
  • BA linked list can't jump straight to the middle.
  • DOne place out of order is enough to send binary search the wrong way.

Why this question

What to teach

  • Requirement 1: the data is in order. Decreasing order works too, with the comparisons flipped.
  • Requirement 2: you can jump straight to the middle. Arrays can; linked lists can't.
  • n numbers need about log₂ n comparisons at most: about 10 for 1000 numbers and about 20 for a million.

Drawing in one stroke

Key point: For one-stroke drawing (in a connected graph), count the odd-degree points: with 0 it works and ends where it started; with 2 it works but must start at one of them; with more than 2 it is impossible.

The figure shows a 'house' graph: a square with both diagonals and a triangular roof on top, giving 5 points and 8 edges (the diagonals cross in the middle, but the crossing is not a point). Can the whole graph be drawn in one stroke, using every edge exactly once?

  1. ANo
  2. BYes, starting from any point
  3. CYes, but only from one of the two bottom corners✓
  4. DYes, but only from the top of the roof

Answer and explanation

Answer: C

Count how many edges meet at each point (this is the point's degree): each bottom corner has 3, each top corner of the square has 4, and the roof has 2. Exactly 2 points have odd degree, the two bottom corners, so the graph can be drawn in one stroke, and the stroke must start at one of these corners and end at the other.

Why the other options are wrong

  • ADidn't count the odd-degree points first. This graph has exactly 2, so it can be done.
  • BStarting anywhere works only when every point has even degree (and then you end where you started).
  • DThe roof point has only 2 edges, so its degree is even.
Teaching question: The rule for drawing in one stroke is short, and once learned it gives an instant answer.

Graph questions (minimum cuts, one-stroke drawing, path counts and so on) are mainly for the Senior Group and appeared in both of the last two Senior papers. One-stroke drawing itself has come up twice (Senior Group, 2016/17 and 2020/21); the rule is simple and worth teaching with one question.

What to teach

  • Degree: the number of edges that meet at a point.
  • 0 odd-degree points: one stroke works and returns to the start. 2: it works, starting at one and ending at the other. More than 2: impossible.
  • Why: passing through a point uses one edge in and one edge out, so edges are used in pairs; only the start and the end can have one left over.

Key point: To compare numbers in different bases, convert them all to decimal first. Remember: eight 1s in binary = hexadecimal FF = 255.

Inclusion–exclusion

Key point: Inclusion–exclusion: the count of 'A or B' = count of A + count of B − count of 'A and B'. For 'divisible by both', use the least common multiple, not the product.

How many numbers from 1 to 100 are divisible by 4 or 6?

  1. A41
  2. B37
  3. C25
  4. D33✓

Answer and explanation

Answer: D

There are 25 multiples of 4 (100 ÷ 4) and 16 multiples of 6 (the whole-number part of 100 ÷ 6). Numbers that are multiples of both are the multiples of 12, the least common multiple of 4 and 6; there are 8 of them (the whole-number part of 100 ÷ 12). They were counted twice, so subtract them once: 25 + 16 − 8 = 33.

Why the other options are wrong

  • ADidn't subtract the numbers that are multiples of both.
  • BAssumed the overlap is multiples of 24 (4 × 6); it is actually multiples of the least common multiple, 12.
  • CCounted only the multiples of 4.

Why this question

Replacing a loop with a formula comes up often in both groups, and both groups had it in 2025/26. Paper 1 code questions often ask how many times a loop runs, and inclusion–exclusion is much faster than counting one by one.

What to teach

  • The number of multiples of k from 1 to n: the whole-number part of n ÷ k.
  • 'Or': add the two counts, then subtract the overlap.
  • Use the least common multiple for the overlap: for 4 and 6 it is 12, not 24.

A game with three piles of stones

Key point: For games, work backwards from the end: a position is winning if some move leads to a losing position, and losing if every move leads to a winning position.

There are three piles of 2, 3 and 4 stones. Two players take turns; on each turn a player takes any number of stones (at least 1) from one pile. Whoever takes the last stone wins. What should the first player do on the first move to be sure of winning?

  1. ATake the whole pile of 4
  2. BTake 3 from the pile of 4✓
  3. CTake 1 from the pile of 3
  4. DThe first player loses whatever they do

Answer and explanation

Answer: B

Work backwards from the end. (1) With just two equal piles left (say 2 and 2), the player to move loses: the opponent always takes the same number from the other pile, so the opponent takes the last stone. (2) With 1, 2 and 3 left, the player to move also loses: whatever they take, the opponent can make two equal piles. For example, if they take the pile of 1, the opponent takes 1 from the pile of 3, leaving 2 and 2. (3) So the first player should take 3 from the pile of 4, leaving 1, 2 and 3 for the opponent.

Going further: if the XOR of all pile sizes is 0, the position is a losing one.
2 ^ 3 ^ 4 = 5 (not 0, so the first player can win)
2 ^ 3 ^ 1 = 0 (after taking 3, the opponent faces a losing position)

Why the other options are wrong

  • AThis leaves 2 and 3. The opponent takes 1 from the pile of 3, leaving 2 and 2, and then wins by copying your moves.
  • CThis leaves 2, 2 and 4. The opponent takes the whole pile of 4, leaving 2 and 2, and then wins by copying your moves.
  • DThe first player does have a winning move: take 3 from the pile of 4.

Why this question

Game questions (winning and losing positions) have been set for both groups, in forms such as taking stones, removing items in turn, placing rooks, and noughts and crosses (tic-tac-toe); all are solved by working backwards from the end. A single pile where each turn takes 1 to k stones can be solved with the rule 'leave a multiple of k + 1'. Three piles do have a rule too (the XOR of the pile sizes), but it is hard to discover on your own, so students must genuinely reason backwards, which goes a little deeper than past papers.

What to teach

  • A losing position: whatever you do, the opponent has an answer.
  • A winning position: at least one move leaves the opponent in a losing position.
  • Two equal piles: the second player wins just by copying.
  • Going further: with any number of piles, the position is losing exactly when the XOR of the pile sizes is 0.
