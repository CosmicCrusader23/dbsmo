第 1 題初級組及高級組單選題1 分 · 建議 2:00

負數的整數除法和類型轉換

重點：整數除法向 0 取整，負數也一樣（−7 / 2 = −3），餘數和被除數同號（−7 % 2 = −1）；存入 double 也救不回小數部分；(double) a / b 先轉換 a，再除。

以下程式輸出甚麼？

int a = -7, b = 2;
double x = a / b;
double y = (double) a / b;
int z = a / b * b + a % b;
cout << x + y + z;
  1. A-13.5✓
  2. B-14.5
  3. C-14
  4. D-13

答案與解說

答案：A

C++ 的整數除法向 0 取整：−7 / 2 = −3（不是 −4），而 −7 % 2 = −1（餘數和被除數同號）。x：a / b = −3，存入 double 後是 −3.0。y：(double) a 先把 a 變成 −7.0，再除以 2，得 −3.5。z：由左至右，a / b * b = −3 × 2 = −6，加上 a % b = −1，得 −7（a / b * b + a % b 一定等於 a）。x + y + z = −3 − 3.5 − 7 = −13.5，輸出 -13.5。

錯誤選項錯在哪裏

  • B以為整數除法向下取整（像數學的 floor），−7 / 2 = −4。C++ 的整數除法向 0 取整：−7 / 2 = −3，−7 % 2 = −1。
  • C以為 double x = a / b 會得 −3.5。a / b 兩邊都是 int，先做整數除法得 −3，存入 double 後才變成 −3.0。
  • D以為 (double) a / b 是把 a / b 的結果轉成 double（−3.0）。其實類型轉換比除法先做：a 先變成 −7.0，−7.0 / 2 = −3.5。

為何會考

整數除法在 16 屆裏有 12 屆考過（難點庫 L01），負數取模有 8 屆（L02）；2025/26 初級卷二甲部考了 (int) a + b + c。

出題說明（給老師）

中等題，四個陷阱放在同一題：負數除法的取整方向、負數的餘數、整數除法存入 double、類型轉換的次序。三個錯誤選項各錯一個地方，都由改寫後的程式實際執行得出。精選 30 題問過「哪些寫法輸出 2.5」；這題加入負數，而且要求和。

第 2 題初級組及高級組單選題1 分 · 建議 2:00

else 跟哪一個 if？

重點：else 總是和最近的、還未有 else 的 if 配對，與縮排無關；不確定時自己加上大括號再讀。

以下程式輸出甚麼？

int c = 0;
for (int x = -2; x <= 2; x++)
    for (int y = -2; y <= 2; y++)
        if (x > 0)
            if (y > 0) c += 1;
        else
            c += 10;
cout << c;
  1. A154
  2. B214
  3. C64✓
  4. D44

答案與解說

答案：C

else 跟最近的、還未配對的 if 配對，所以迴圈內等於 if (x > 0) { if (y > 0) c += 1; else c += 10; }，x ≤ 0 時甚麼都不做。x = 1、2 時：y = 1、2 各加 1，y = −2、−1、0 各加 10，每個 x 加 2 + 30 = 32。兩個 x 共 64，輸出 64。

錯誤選項錯在哪裏

  • A按縮排以為 else 屬於外層的 if (x > 0)：那就是 x > 0、y > 0 時加 1（4 次），x ≤ 0 時加 10（15 次）。C++ 的 else 總是跟最近的、還未配對的 if，即 if (y > 0)；縮排不影響意思。
  • B以為 else 在「兩個條件不是都成立」時執行：x > 0 而且 y > 0 時加 1（4 次），其餘 21 次都加 10。else 只屬於一個 if。
  • Delse 的配對正確，但數漏了 y = 0：y > 0 不成立的 y 有 −2、−1、0 三個，所以 x = 1、2 時各加 30。

為何會考

if/else 的結構陷阱在 16 屆裏有 9 屆考過（難點庫 L18）；2025/26 初級卷一甲部也考了 if 和 else 的規則。

出題說明（給老師）

中等題：縮排故意誤導（考到這個陷阱時通常如此），而且要在 25 組 (x, y) 中數清楚。答案和每個錯誤選項都用程式核對過：把 else 改配外層的 if 會輸出 154。

第 3 題初級組及高級組單選題1 分 · 建議 2:00

一個引用參數，一個普通參數

重點：參數名稱前有 & 才是引用：在函數裏改它，就是改調用時傳入的變量；沒有 & 的參數只是副本。調轉參數次序調用時，被改的就是另一個變量。

以下程式輸出甚麼？

void g(int &x, int y) {
    x += y;
    y += x;
}
int main() {
    int a = 1, b = 2;
    for (int i = 0; i < 3; i++) {
        g(a, b);
        g(b, a);
    }
    cout << a << " " << b;
}
  1. A1 2
  2. B379 268
  3. C127 65
  4. D21 34✓

答案與解說

答案：D

g 只會改第一個參數：g(a, b) 等於 a += b，g(b, a) 等於 b += a；y += x 只改副本。(a, b) 依次是 (1, 2) → (3, 2) → (3, 5) → (8, 5) → (8, 13) → (21, 13) → (21, 34)，輸出 21 34。

錯誤選項錯在哪裏

  • A以為兩個參數都只是副本，a、b 都不變。其實 x 是引用（int &x），改 x 就是改傳入的第一個變量。
  • B以為兩個參數都是引用，於是 y += x 也會改傳入的第二個變量。其實 y 不是引用，y += x 只改函數裏的副本。
  • C把兩個參數的角色調轉了：以為 y 是引用、x 是副本。

為何會考

引用參數與別名在 16 屆裏有 5 屆考過（難點庫 L15）；2024/25 初級卷二甲部考了 f(++a, ++b)。

出題說明（給老師）

中等題。精選 30 題考過 f(a, a)；這題一個引用、一個副本，而且交替用 g(a, b)、g(b, a) 調用六次。三個錯誤選項分別是全部當副本、全部當引用、角色調轉，都由改了 & 位置的程式實際執行得出。

第 4 題初級組及高級組單選題1 分 · 建議 2:00

位元運算的優先次序

重點：&、^、| 比 == 低：a & b == c 是 a & (b == c)。位移 <<、>> 比 == 高，但比 +、− 低：2 << 1 == 4 是 (2 << 1) == 4，值為 1；1 << 2 + 1 是 1 << 3。& 先於 ^ 先於 |。不肯定就加括號。

以下程式輸出甚麼？

int a = 6, b = 13;
cout << (a & b == 4) << " " << (a << 1 + 1) << " " << (a ^ b | a & 3);
  1. A1 24 11
  2. B0 24 11✓
  3. C0 13 11
  4. D1 13 3

答案與解說

答案：B

C++ 的優先次序：+ 先於 <<，<< 先於 ==，== 先於 &，& 先於 ^，^ 先於 |。第一個：b == 4 是 0，6 & 0 = 0。第二個：1 + 1 = 2，6 << 2 = 24。第三個：先算 a & 3 = 110 & 011 = 010 = 2，再算 a ^ b = 0110 ^ 1101 = 1011 = 11，最後 11 | 2 = 1011 | 0010 = 1011 = 11。輸出 0 24 11。

錯誤選項錯在哪裏

  • A以為 & 先於 ==。其實 == 先計算：b == 4 是 0，6 & 0 = 0。
  • C以為 << 先於 +。其實 + 先計算：1 + 1 = 2，6 << 2 = 24。
  • D全部由左至右計算：(6 & 13) == 4 得 1，(6 << 1) + 1 得 13，((6 ^ 13) | 6) & 3 得 3。

為何會考

位元運算和優先次序在 16 屆裏有 9 屆考過（難點庫 L27）。

出題說明（給老師）

位元運算求值在 16 屆裏有 9 屆考過（難點庫 L27），優先次序是 Kahoot v1 第 12、13 題的考點。這題把三個優先次序陷阱放在一起，四個選項分別是全對、第一部分錯、第二部分錯和全部由左至右計算，都由程式計算得出。

第 5 題初級組及高級組單選題1 分 · 建議 2:00

&& 和 || 裏的 ++

重點：&& 先於 ||；&& 左邊不成立、|| 左邊成立時，右邊都不會計算，右邊的 ++ 也不會執行。

以下程式輸出甚麼？

int a = 0, b = 0, c = 0;
for (int i = 1; i <= 10; i++)
    if (i % 2 == 0 && ++a > 2 || i % 3 == 0 && ++b > 1)
        c++;
cout << a << " " << b << " " << c;
  1. A5 3 4
  2. B10 10 6
  3. C5 2 4✓
  4. D5 3 2

答案與解說

答案：C

&& 先於 ||，所以條件是「(i 是偶數 && ++a > 2) || (i 是 3 的倍數 && ++b > 1)」。&& 左邊不成立時不計算右邊；|| 左邊成立時也不計算右邊。偶數的 i（2、4、6、8、10）都會令 a 加 1，a 最後是 5；由 i = 6 起 ++a > 2 成立，c 在 i = 6、8、10 各加 1，而且這三次右邊都不計算。左邊不成立時才計算右邊：i = 2、4 不是 3 的倍數；i = 3 時 b 變成 1，不大於 1；i = 9 時 b 變成 2，條件成立，c 再加 1。i = 6 雖然是 3 的倍數，但左邊已經成立，++b 不會執行。所以 a = 5，b = 2，c = 4。

錯誤選項錯在哪裏

  • A以為 || 左邊成立時，右邊仍然會計算。i = 6 時左邊已經成立，右邊的 ++b 不會執行，所以 b 只在 i = 3 和 i = 9 時加 1。
  • B以為 && 和 || 兩邊都一定會計算，於是 ++a、++b 每次都執行。其實 && 左邊不成立時，右邊不會計算。
  • D把條件看成 i % 2 == 0 && (++a > 2 || i % 3 == 0) && ++b > 1。其實 && 先於 ||，條件是兩個 && 部分用 || 連接。

為何會考

短路求值在 16 屆裏有 3 屆考過（難點庫 L12）。

出題說明（給老師）

短路求值在 16 屆裏有 3 屆考過（難點庫 L12），Kahoot v1 也考過。這題把 ++ 放在兩個不同位置，三個錯誤選項分別來自完全不懂短路、只懂 && 的短路和看錯優先次序，每個都由改寫後的程式實際執行得出。三個數各取最多選項的值，會得到錯誤的 5 3 4，所以不能靠選項推答案。

第 6 題初級組及高級組填充題1.5 分 · 建議 3:00

continue 之前先 i++

重點：在迴圈裏改 i 之後再 continue，for 的 i++ 仍然會執行，等於多走一步；break 立即結束整個迴圈。要留意檢查在加之前還是之後。

以下程式輸出甚麼？

int s = 0;
for (int i = 1; i <= 100; i++) {
    if (i % 4 == 0) { i++; continue; }
    if (s > 100) break;
    s += i;
}
cout << s;

只填一個整數。

L：

答案與解說

答案：L：106

i 是 4 的倍數時，先 i++，再 continue，for 的 i++ 又執行一次，所以 4、5 都被跳過，8、9 都被跳過，如此類推。加上的數依次是 1、2、3、6、7、10、11、14、15、18、19：s 依次是 1、3、6、12、19、29、40、54、69、87、106。下一個 i 是 20（4 的倍數），跳到 22；這時 s = 106 > 100，break。輸出 106。

常見錯誤答案

  • 113：以為只是跳過 4 的倍數。其實 i 是 4 的倍數時，迴圈裏先 i++，continue 之後 for 又 i++，所以 4 的倍數的下一個數（5、9、13、…）也被跳過。
  • 87：以為 s 不會超過 100。其實檢查在加之前：i = 19 時 s = 87，不大於 100，所以加上 19 得 106；到 i = 22 時才停。

為何會考

break、continue 與迴圈次數在 16 屆裏有 9 屆考過（難點庫 L19）；2024/25 初級卷一乙部考了在迴圈中修改自己的邊界。

出題說明（給老師）

中等題：continue 之後 for 的 i++ 仍然執行，加上在迴圈中改 i，兩個陷阱疊在一起。答案由程式執行得出；錯誤答案 113、87 分別由刪去迴圈中的 i++、把檢查改為 s + i > 100 的程式得出。

第 7 題初級組及高級組填充題1.5 分 · 建議 3:00

最長的上升段（程式有錯）

重點：讀「想做某件事」的程式時，要照程式實際做的追蹤；找錯時特別留意初值（0 還是 1）和最後一段有沒有處理。

以下程式想輸出陣列 a 之中最長的「連續上升段」的長度（例如 2 3 5 是長度 3 的上升段）。程式實際輸出甚麼？

int a[8] = {4, 6, 7, 2, 3, 5, 8, 9};
int best = 0, cur = 0;
for (int i = 1; i < 8; i++) {
    if (a[i] > a[i - 1]) cur++;
    else {
        best = max(best, cur);
        cur = 0;
    }
}
cout << best;

只填一個整數。

M：

答案與解說

答案：M：2

i = 1、2：6 > 4、7 > 6，cur 變成 1、2。i = 3：2 < 7，best = max(0, 2) = 2，cur = 0。i = 4 至 7：3、5、8、9 都比前一個大，cur 變成 1、2、3、4，但之後再沒有不上升的情況，迴圈結束時 cur = 4 沒有和 best 比較。輸出 2。要改正：cur 的初值改為 1，上升段斷開時 cur 也重設為 1（一個數本身是長度 1 的段），並在迴圈結束後再做一次 best = max(best, cur)。

常見錯誤答案

  • 5：照程式的「目的」作答：最長的上升段是 2 3 5 8 9，長度 5。但程式有兩個錯：cur 數的是上升了幾次（比段長少 1），而且最後一段在迴圈結束後沒有和 best 比較。
  • 4：發現了 cur 比段長少 1，卻沒有發現最後一段 2 3 5 8 9 從未和 best 比較。
  • 3：發現了最後一段沒有比較，卻以為 cur 就是段長：4 6 7 的長度是 3。

為何會考

累加、更新與初值在 16 屆裏有 12 屆考過（難點庫 F05），2023/24 有 4 題；改錯題「拿邊界輸入去試」有 12 屆（F08）。

出題說明（給老師）

容易至中等題，兩個錯誤疊在一起：錯誤答案 5、4、3 分別是兩個錯都沒看到、只看到一個。答案和錯誤答案都由程式（及改正了其中一個錯的版本）實際執行得出。

第 8 題初級組及高級組填充題1.5 分 · 建議 3:00

字母移位和 XOR 1

重點：字母變序號用 c - 'A'，序號變回字母用 + 'a'（小寫）或 + 'A'（大寫）；^ 是 XOR，不是次方，^ 1 只改變最低的一位。

以下程式輸出甚麼？

string s = "HKOI2026";
for (int i = 0; i < s.size(); i++) {
    if (s[i] >= 'A' && s[i] <= 'Z')
        s[i] = (s[i] - 'A' + 3 * i) % 26 + 'a';
    else
        s[i] = s[i] ^ 1;
}
cout << s;

照輸出逐個字元填寫，注意大小寫，不用加空格。

N：

答案與解說

答案：N：hnur3137

大寫字母：先用 s[i] - 'A' 變成 0 至 25 的序號，加 3 × i，取除以 26 的餘數，再加 'a' 變成小寫字母。H（7 + 0 = 7）→ h；K（10 + 3 = 13）→ n；O（14 + 6 = 20）→ u；I（8 + 9 = 17）→ r。數字字元：^ 1 反轉 ASCII 碼最低的一位。'2' 是 50、'0' 是 48、'6' 是 54，都是偶數，XOR 1 之後加 1，變成 '3'、'1'、'3'、'7'。輸出 hnur3137。

常見錯誤答案

  • hnur2026：把 ^ 當成次方，以為 ^ 1 不改變數字。^ 是 XOR：'2' 是 50，50 ^ 1 = 51，即 '3'。
  • HNUR3137：漏了轉成小寫：程式加的是 'a'，不是 'A'。

為何會考

字元與 ASCII 碼互換，16 屆裏有 9 屆考過（難點庫 L07）。

出題說明（給老師）

字元與數字互換在 16 屆裏有 9 屆考過（難點庫 L07）；精選 30 題考過 'q' ^ 32。這題每個位置的位移不同，數字字元又要用 XOR，兩個錯誤答案分別來自把 ^ 當成次方和漏了轉成小寫。答案用程式執行核對過。

第 9 題初級組及高級組填充題1.5 分 · 建議 3:00

剛好兩個相等

重點：比較的結果 true、false 在 C++ 裏可以當 1、0 計算：「剛好 k 個條件成立」可以寫成把條件加起來 == k。

填寫空格 O，令函數在 a、b、c 之中剛好有兩個相等時傳回 true；三個都相等，或者三個互不相同時，傳回 false。

bool twoEqual(int a, int b, int c) {
    return O;
}

只填一個條件（運算式），可以用 a、b、c、整數和運算符，最多 40 格（空白不計）。

O：

答案與解說

答案：O：(a == b) + (b == c) + (a == c) == 1

「剛好兩個相等」等於「三個比較 a == b、b == c、a == c 之中剛好一個成立」：如果有兩個成立，例如 a == b 和 b == c，第三個 a == c 也一定成立。C++ 的 true、false 可以當作 1、0 相加，所以可以寫 (a == b) + (b == c) + (a == c) == 1。另一種寫法是「最少一對相等，但不是三個都相等」：(a == b || b == c || a == c) && !(a == b && b == c)。網頁會代入 a、b、c 的不同數值，和參考答案比較。

常見錯誤答案

  • a == b || b == c || a == c：三個都相等時也會傳回 true。
  • (a == b) ^ (b == c) ^ (a == c)：剛好一對相等時是 true，但三個都相等時三個比較都是 true，XOR 起來仍是 true。
  • (a == b) + (b == c) + (a == c) == 2：三個比較不可能剛好兩個成立：a == b 和 b == c 都成立時，a == c 也一定成立。

答案與解說

答案：P：2027

先試小的 n（f(n) 是 1 至 n 全部 XOR 起來）：f(1) = 1，f(2) = 1 ^ 2 = 3，f(3) = 3 ^ 3 = 0，f(4) = 4，f(5) = 1，f(6) = 7，f(7) = 0，f(8) = 8。規律：n 除以 4 餘 0 時 f(n) = n，餘 1 時是 1，餘 2 時是 n + 1，餘 3 時是 0。原因：k 是偶數時，k 和 k + 1 只差最低一位，k ^ (k + 1) = 1；所以由 4 的倍數開始，每 4 個連續的數 XOR 起來是 1 ^ 1 = 0。2026 = 4 × 506 + 2，所以 f(2023) = 0，再 ^ 2024 ^ 2025 ^ 2026：2024 ^ 2025 = 1，1 ^ 2026 = 2027。輸出 2027。

常見錯誤答案

答案：Q：246

字串壓縮

重點：找一段相同的字母：j 由 i 開始，條件 j < n && s[j] == s[i]；這一段是 s[i] 至 s[j − 1]，長度 j − i，下一段由 j 開始。

以下程式把只有小寫英文字母的字串壓縮：連續相同的字母寫成「字母加次數」，只出現一次的不寫次數，例如 aaabccddddd 變成 a3bc2d5。在空格 R、S、T 填上適當的內容，使程式正確。

int main() {
    string s, t = "";
    cin >> s;
    int i = 0, n = s.size();
    while (i < n) {
        int j = i;
        while (j < n && R) j++;
        t += s[i];
        if (j > i + 1) t += to_string(S);
        i = T;
    }
    cout << t;
}

R 填一個條件，例如 a[k] != 0；S、T 只填算式，可以用 i、j、整數和運算符，最多 12 格（空白不計）。每格 1 分。

R：S：T：

答案與解說

答案：R：s[j] == s[i]；S：j - i；T：j

j 由 i 開始向右走，走到第一個和 s[i] 不同的字母（或字串結尾）為止，所以 R 是 s[j] == s[i]（j < n 寫在前面，保證不會超出字串）。這一段相同的字母是 s[i] 至 s[j − 1]，共 j − i 個；多於一個（j > i + 1）才寫次數，所以 S 是 j - i。下一段由 j 開始，所以 T 是 j（即 i = j）。例如 aaabccddddd：aaa → a3，b → b，cc → c2，ddddd → d5，輸出 a3bc2d5。

常見錯誤答案

  • S：j - i + 1：多算了一個。這一段是 s[i] 至 s[j − 1]，共 j − i 個字母：j 停在第一個不同的字母上。
  • T：j + 1：跳過了 s[j]。s[j] 是下一段的第一個字母，下一段應由 j 開始。
  • R：s[j] == s[j + 1]：比較了相鄰的兩個字母：j 停在這一段的最後一個字母上，長度少算一個；之後 i = j，下一輪 j 不會前進，程式永遠不會停（例如輸入 aaab）。應該和這一段的第一個字母 s[i] 比較。

Integer division of negatives, and casts

Key point: Integer division rounds toward 0, negatives included (−7 / 2 = −3), and the remainder has the sign of the number divided (−7 % 2 = −1); storing in a double cannot bring back the fraction; (double) a / b converts a first, then divides.

What does this program print?

int a = -7, b = 2;
double x = a / b;
double y = (double) a / b;
int z = a / b * b + a % b;
cout << x + y + z;
  1. A-13.5✓
  2. B-14.5
  3. C-14
  4. D-13

Answer and explanation

Answer: A

C++ integer division rounds toward 0: −7 / 2 = −3 (not −4), and −7 % 2 = −1 (the remainder takes the sign of the number being divided). x: a / b = −3, stored as −3.0. y: (double) a turns a into −7.0 first, and dividing by 2 gives −3.5. z: left to right, a / b * b = −3 × 2 = −6, plus a % b = −1 gives −7 (a / b * b + a % b always equals a). x + y + z = −3 − 3.5 − 7 = −13.5, so the output is -13.5.

What is wrong with each wrong option

  • BAssumes integer division rounds down (like floor), so −7 / 2 = −4. C++ integer division rounds toward 0: −7 / 2 = −3 and −7 % 2 = −1.
  • CThinks double x = a / b gives −3.5. Both sides of a / b are int, so integer division gives −3 first, which only then becomes −3.0.
  • DThinks (double) a / b converts the result of a / b (−3.0). The cast happens before the division: a becomes −7.0, and −7.0 / 2 = −3.5.

What does this program print?

for (int x = -2; x <= 2; x++)
    for (int y = -2; y <= 2; y++)

  2. B214
  3. C64✓
  4. D44

Answer and explanation

Answer: C

An else pairs with the nearest unmatched if, so the loop body means if (x > 0) { if (y > 0) c += 1; else c += 10; }, and nothing happens when x ≤ 0. For x = 1 and 2: y = 1, 2 each add 1 and y = −2, −1, 0 each add 10, so each x adds 2 + 30 = 32. The two give 64, so the output is 64.

Key point: Only a parameter with & is a reference: changing it in the function changes the variable passed in; a parameter without & is just a copy. Calling with the arguments swapped changes the other variable.

What does this program print?

void g(int &x, int y) {
    x += y;
    y += x;
}
int main() {
    int a = 1, b = 2;
    for (int i = 0; i < 3; i++) {
        g(a, b);
        g(b, a);
    }
    cout << a << " " << b;
}
  1. A1 2
  2. B379 268
  3. C127 65
  4. D21 34✓

Answer and explanation

Answer: D

g changes only its first argument: g(a, b) means a += b and g(b, a) means b += a; y += x changes only the copy. (a, b) goes (1, 2) → (3, 2) → (3, 5) → (8, 5) → (8, 13) → (21, 13) → (21, 34), so the output is 21 34.

Precedence of bitwise operators

Key point: &, ^ and | bind more loosely than ==: a & b == c means a & (b == c). The shifts << and >> bind more tightly than == but more loosely than + and −: 2 << 1 == 4 means (2 << 1) == 4, which is 1, and 1 << 2 + 1 means 1 << 3. & comes before ^, which comes before |. When unsure, add brackets.

What does this program print?

int a = 6, b = 13;
cout << (a & b == 4) << " " << (a << 1 + 1) << " " << (a ^ b | a & 3);
  1. A1 24 11
  2. B0 24 11✓
  3. C0 13 11
  4. D1 13 3

Answer and explanation

Answer: B

C++ precedence: + before <<, << before ==, == before &, & before ^, ^ before |. First: b == 4 is 0, and 6 & 0 = 0. Second: 1 + 1 = 2, and 6 << 2 = 24. What is wrong with each wrong option

  • CThinks << comes before +. In fact + is evaluated first: 1 + 1 = 2, and 6 << 2 = 24.
  • DEvaluates everything left to right: (6 & 13) == 4 gives 1, (6 << 1) + 1 gives 13, and ((6 ^ 13) | 6) & 3 gives 3.

++ inside && and ||

Key point: && binds tighter than ||; when the left side of && is false or the left side of || is true, the right side is not evaluated, and any ++ on it does not run.

What does this program print?

    if (i % 2 == 0 && ++a > 2 || i % 3 == 0 && ++b > 1)
        c++;

  2. B10 10 6
  3. C5 2 4✓
  4. D5 3 2

Answer and explanation

Answer: C

&& binds tighter than ||, so the condition is (i even && ++a > 2) || (i a multiple of 3 && ++b > 1). When the left side of && is false, its right side is not evaluated; when the left side of || is true, its right side is not evaluated either. Every even i (2, 4, 6, 8, 10) increases a, so a ends at 5; from i = 6 on, ++a > 2 is true, so c increases at i = 6, 8 and 10, and in those three passes the right side is never evaluated. The right side is evaluated only when the left side is false: i = 2 and 4 are not multiples of 3; at i = 3, b becomes 1, which is not more than 1; at i = 9, b becomes 2, the condition holds and c increases again. Although 6 is a multiple of 3, the left side is already true at i = 6, so ++b does not run. So a = 5, b = 2, c = 4.

What is wrong with each wrong option

  • AThinks the right side of || is still evaluated when the left side is true. At i = 6 the left side is already true, so ++b on the right does not run; b only increases at i = 3 and i = 9.
  • BThinks both sides of && and || are always evaluated, so ++a and ++b run every time. In fact, when the left side of && is false, its right side is not evaluated.
  • DReads the condition as i % 2 == 0 && (++a > 2 || i % 3 == 0) && ++b > 1. In fact && binds tighter than ||, so the condition is two && parts joined by ||.

O:

Answer and explanation

Answer: O: (a == b) + (b == c) + (a == c) == 1

"Exactly two are equal" means "exactly one of the comparisons a == b, b == c, a == c holds": if two hold, say a == b and b == c, then a == c holds as well. Key point: For XOR over a large range, try small n to find the pattern; for even k, k ^ (k + 1) = 1, so every 4 consecutive numbers from a multiple of 4 XOR to 0.

    x ^= i;

P:

Answer and explanation

Answer: P: 2027

Try small n first (f(n) is the XOR of 1 to n): f(1) = 1, f(2) = 1 ^ 2 = 3, f(3) = 3 ^ 3 = 0, f(4) = 4, f(5) = 1, f(6) = 7, f(7) = 0, f(8) = 8.   • 2026: Assumes the result is n. f(n) = n is the rule for remainder 0 when divided by 4; 2026 leaves remainder 2, so use n + 1.

Compressing a string

Key point: To find a run of equal letters: start j at i with the condition j < n && s[j] == s[i]; the run is s[i] to s[j − 1], of length j − i, and the next run starts at j.

int main() {
    string s, t = "";
    cin >> s;
    int i = 0, n = s.size();
    while (i < n) {
        int j = i;
        while (j < n && R) j++;
        t += s[i];
        if (j > i + 1) t += to_string(S);
        i = T;
    }
    cout << t;
}

R:S:T:

Answer and explanation

Answer: R: s[j] == s[i]; S: j - i; T: j

j starts at i and moves right until the first letter different from s[i] (or the end), so R is s[j] == s[i] (with j < n first, so j never runs past the end). The run is s[i] to s[j − 1], j − i letters, and the count is written only when there is more than one (j > i + 1), so S is j - i. The next run starts at j, so T is j (that is, i = j).
